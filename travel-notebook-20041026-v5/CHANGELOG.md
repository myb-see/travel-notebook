# 改造记录

## 2026-07-26 (v5)

- 实现模型自适应请求管道（Provider-Adaptive Request Pipeline）：
  - 当使用 `gemini` 时：启用双通道并行并发（Parallel Streaming），极速打字生成。
  - 当使用 `glm` 时：启用串行队列保护（Serial Pipeline），彻底消除免费账号的 429 (Error 1302) 速率限制报错。
- 支持无缝顺畅体验 `glm-4.7-flash` 最新逻辑推理与思维链能力，避免离线降级。

## 2026-07-25 (v4) — 合并最优版

- 合并 v4 两版实现的优点：以数据驱动 `PROVIDER_ENV_MAP` 结构为骨架。
- 保留 `source` 字段追踪配置来源（gemini / glm / legacy / coze）。
- 保留旧版 `AI_API_KEY` 回退兼容与 URL 尾斜杠处理。
- 统一命名风格，补充注释。

## 2026-07-25 (v4)

- 新增 AI 模型自由切换：用户可在表单中选择 Gemini Flash 或 GLM Flash。
- 结果页增加模型切换按钮：保留当前旅行参数，一键切换模型重新生成攻略与行李清单。
- 模型偏好保存在浏览器 localStorage，下次访问自动恢复。
- 结果页显示当前使用的 AI 模型标签。
- 收藏和分享内容保留 AI 模型信息；旧数据默认按 Gemini 兼容读取。
- Gemini 与 GLM 使用独立的服务端环境变量（GEMINI_API_KEY / GLM_API_KEY）。
- 保留旧版 AI_API_KEY 单接口配置兼容；未配置时回退到扣子运行环境。
- /api/health 可分别检查两套接口的配置状态。
- 前端仅提交 gemini 或 glm，不能传入自定义 API 地址，密钥不暴露给浏览器。
- 未配置或接口异常时，仍返回离线降级攻略与行李清单。
